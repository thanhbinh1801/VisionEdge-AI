# BUG-001 — Area dashboard renders duplicate bounding boxes for the same object

- Severity: major
- Affected requirements: `REQ-002`, `REQ-009`
- Affected tasks: `TASK-018`, `TASK-017`

## Expected

`Area Security Dashboard` should show one visual bounding box per detected object in the live area view.

## Actual

The same detected object is rendered twice on screen: one box comes from the MJPEG stream image, and another box is drawn by the frontend metadata overlay. This makes operators think the detector produced duplicate detections even when the pipeline may only have emitted one object.

## Reproduction

1. Open the area dashboard for camera `BAI-KIEM`.
2. Wait until the live view and metadata lane are both online.
3. Observe a detected object in the live scene.
4. Notice that the viewport shows two boxes layered around the same object instead of one.

## Evidence

- Frontend uses MJPEG stream as the base renderer:
  - [AreaSecurityDashboard.tsx](D:/Hilab/Project34/frontend/src/pages/AreaSecurityDashboard.tsx:168) builds the `video-feed` URL.
  - [AreaSecurityDashboard.tsx](D:/Hilab/Project34/frontend/src/pages/AreaSecurityDashboard.tsx:295) renders that stream with `<img src={videoSrc}>`.
- Frontend also draws object boxes again from metadata lane:
  - [AreaSecurityDashboard.tsx](D:/Hilab/Project34/frontend/src/pages/AreaSecurityDashboard.tsx:311) mounts the metadata overlay SVG.
  - [AreaSecurityDashboard.tsx](D:/Hilab/Project34/frontend/src/pages/AreaSecurityDashboard.tsx:324) iterates `metadataObjects.map(...)` and draws `<rect>` for each object.
- Backend MJPEG route still draws detection boxes into the image itself:
  - [events.py](D:/Hilab/Project34/backend/app/api/v1/events.py:127) iterates `snapshot.detections`.
  - [events.py](D:/Hilab/Project34/backend/app/api/v1/events.py:153) calls `cv2.rectangle(...)` for each detection.
- Task implementation note already states frontend added client-side bbox overlay on top of MJPEG:
  - [TASK-RESULT.md](D:/Hilab/Project34/.delivery/tasks/TASK-018/TASK-RESULT.md:27)

## Root Cause

The integrated area dashboard currently has two bbox renderers active at the same time:

- backend MJPEG lane burns detection rectangles directly into the image frame
- frontend metadata lane draws another rectangle for the same object on top of that image

Because `TASK-018` introduced client-side bbox overlay while still consuming a stream produced by the `TASK-017` renderer, the same visual entity is rendered twice.

## Regression Test

- Status: not added
- Recommended seam:
  - frontend integration test or visual regression around `AreaSecurityDashboard`
  - or contract-level assertion that when metadata overlay is enabled, MJPEG object boxes are disabled for that view

## Recommended Fix Phạm vi

- Choose one bbox renderer as the source of truth for the area dashboard:
  - either keep MJPEG object boxes and remove frontend object-box overlay
  - or keep metadata overlay and stop drawing object boxes into the MJPEG stream for this consumer
- Keep zone polygons and labels aligned with the chosen renderer so operators still see zone context.

## Open Questions

- Does the team want the area dashboard to treat metadata lane as the only overlay source, with MJPEG carrying pixels only?
- Should the MJPEG route expose an explicit flag to disable object boxes independently from zone polygons for area consumers?
