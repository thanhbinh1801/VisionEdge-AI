# BUG-001 - Area event API omits zone_name expected by Area Dashboard event feed

- Severity: major
- Affected requirements: `REQ-002`, `REQ-009`, `CR-003`
- Owning task: `TASK-017` - Backend area metadata lane and event persistence lane
- Affected downstream task: `TASK-018`
- Discovered by: `TASK-019` CR-003 verification
- Recorded at: `2026-08-23T15:26:13+07:00`

## Expected

`GET /api/v1/events` should provide enough zone context for Area Dashboard event feed rows to show the violated or allowed zone name.

After CR-003, metadata, video stream, and event/alert lanes are separated, but the event lane still needs operator-facing area context.

## Actual

`frontend/src/pages/AreaSecurityDashboard.tsx` maps the feed zone label from `evt.zone_name || 'Ngoài zone'`.

The route-local `EventResponse` in `backend/app/api/v1/events.py` exposes `zone_id` but omits `zone_name`, so API responses cannot satisfy the frontend expectation. Area events with valid `zone_id` cần render as "Ngoài zone".

## Reproduction

Static reproduction:

```powershell
rg -n "class EventResponse|zone_name" backend\app\api\v1\events.py frontend\src\pages\AreaSecurityDashboard.tsx
```

Observed evidence:

```text
frontend\src\pages\AreaSecurityDashboard.tsx:111: zone: evt.zone_name || 'Ngoài zone',
backend\app\api\v1\events.py:34:class EventResponse(BaseModel):
```

`backend/app/api/v1/events.py` route-local response model fields:

```text
id, timestamp, camera_id, zone_id, lane_id, event_type, severity_level,
license_plate, object_class, confidence, bbox, crop_image_url, video_clip_url
```

The separate schema file `backend/app/models/schemas/event.py` does include `zone_name`, but this is not the model used by the events route response.

Import note:

Running the route model import directly exposed a secondary import-path fragility:

```text
ModuleNotFoundError: No module named 'app'
```

from project root, and:

```text
ModuleNotFoundError: No module named 'backend'
```

from `backend/`, because `events.py` mixes `app.*` and `backend.*` imports. That is not the primary root cause of this bug, but it makes direct contract introspection harder.

## Minimal Failing Case

1. Persist an event with `zone_id='zK2'`.
2. Return it through `GET /api/v1/events`.
3. The serialized response has `zone_id` but no `zone_name`.
4. Area Dashboard maps `evt.zone_name || 'Ngoài zone'`.
5. UI displays "Ngoài zone" despite a valid zone association.

## Root Cause

The backend event lane response contract implemented in `backend/app/api/v1/events.py` is missing `zone_name` even though the UI and the shared schema expect that field.

This belongs primarily to `TASK-017` because that task owns the backend event persistence/area lane compatibility after CR-003. `TASK-018` is affected, but the frontend is already consuming a plausible event context field and cannot recover the zone name if the event API does not provide it or an equivalent zone lookup path.

## Risk

- Operators lose event location context in the area feed.
- Severity-3 alerts remain less actionable because the UI cần show a violation without the zone name.
- CR-003 verification remains failed for event/alert lane compatibility even if metadata lane itself works.

## Regression Test

No regression test was added in this bug-recording step because the request scope is documentation/diagnosis only.

Recommended failing regression test for the fix owner:

1. Seed a zone and a `ZONE_VIOLATION` event with that `zone_id`.
2. Call `GET /api/v1/events?camera_id=BAI-KIEM`.
3. Assert the response item contains `zone_name` matching the zone record.
4. Assert existing `zone_id` remains present for backward compatibility.

## Recommended Fix Phạm vi

1. Add `zone_name: str | None = None` to the route-local `EventResponse`, or replace it with the shared schema that already includes `zone_name`.
2. Populate `zone_name` from the related zone record or from event metadata at persistence time.
3. Keep the change additive; do not remove `zone_id`.
4. Add an API contract regression test around `GET /api/v1/events`.

## Open Questions

- Should `zone_name` be persisted on every event row, derived by join from `zone_id`, or resolved by the frontend from a zone cache?
- Should the route-local `EventResponse` be consolidated with `backend/app/models/schemas/event.py` to avớid schema drift?
- Should the mixed `app.*`/`backend.*` import path issue be handled as a separate backend hygiene bug?
