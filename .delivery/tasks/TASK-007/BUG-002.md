## Symptoms

When vehicles (cars, trucks, containers) pass through the inbound lane zones (`Làn IN 1`, `Làn IN 2`) of the `GATE-01` gate camera, the system does not recognize the license plate character string and does not emit `LPR_PASSAGE` events into the `events` table in the database. Consequently, the Gate Dashboard UI displays an empty license plate list and unpopulated KPI cards.

## Reproduction Steps

1. Start the backend server and open the Tab 1 UI (Gate Monitoring — Gate Dashboard).
2. Observe the "Vehicle license plate in/out list" table and the 4 KPI cards.
3. Observe that no license plate event is ever detected or recorded from the `GATE-01` video stream.

## Root Cause

In `backend/app/services/vision_pipeline.py`, the pipeline currently only loads the `yolov8s-worldv2.pt` model for detecting 8 generic object classes. The license plate detection/cropping step and the OCR engine (EasyOCR) required by `.delivery/ARCHITECTURE.md` and `.delivery/REQUIREMENTS.md` (`REQ-001`) are missing. Furthermore, `requirements.txt` does not include `easyocr`, and the `events` table never receives `LPR_PASSAGE` records from live stream processing.

## Scope of Impact

- **Affected Tasks**: `TASK-007`, `TASK-009`
- **Affected Requirements**: `REQ-001`
- **Affected Files**:
  - `requirements.txt`
  - `backend/app/services/vision_pipeline.py`
  - `backend/app/api/v1/events.py`

## Applied Fix

1. Added `easyocr>=1.7.0` to `requirements.txt`.
2. Added `backend/app/services/lpr_engine.py` — a dedicated `LPREngine` rather than an extension of `vision_pipeline.py`, because the two have different lifecycles: YOLO-World loads at startup for all three cameras, while EasyOCR is only ever needed for `GATE-01`. The reader is lazy-loaded on the first plate read (`get_reader()`), so opening the area monitoring tab never pays the torch/model-download cost. `extract_license_plate(frame, bbox)` crops the lower part of the vehicle box (the front/rear plate region), preprocesses it (grayscale → upscale → CLAHE → adaptive threshold), runs OCR, and normalizes the result to the Vietnamese plate format (`29A-123.45`, `15C-678.90`, `51B-456.78`), returning `(plate_text, confidence)` and rejecting anything below the confidence threshold.
3. Added the gate event pipeline to `backend/app/api/v1/events.py`: `persist_gate_lpr_events()` runs OCR for `car`/`truck`/`container`/`motorbike` detections inside inbound lane zones, deduplicates per plate through a dedicated `lpr_event_manager` cooldown, resolves the vehicle tag against the `vehicles` table (`known` → severity 1, `unknown` → 2, `blacklisted` → 3), persists an `LPR_PASSAGE` event, and accumulates the four gate counters in `kpi_realtime_cache`. It is invoked from `GET /events/live-detections` when `camera_id == "GATE-01"` — the background decode thread in `video_stream.py` has no DB session, whereas that endpoint already holds both the frame and the session.
4. Added `OCR_CONFIDENCE_THRESHOLD` (default `0.70`) and `LPR_COOLDOWN_SECONDS` (default `12`, validated to the 10–15s range) to `backend/app/core/config.py` and `.env.example`.

## Known Limitation

`REQ-001` acceptance criterion 1 states a plate confidence of **>= 85%**, while the implemented threshold is **0.70** as specified in the fix request. The value is configurable through `OCR_CONFIDENCE_THRESHOLD`; raising it to `0.85` requires no code change. This gap is intentional and needs a product decision.
