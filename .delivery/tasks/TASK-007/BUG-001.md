## Symptoms

In the `BAI-KIEM` scene, a vertical pole/column is sometimes detected as `Xe cẩu` (`crane`). The area vision pipeline should classify fixed scene structures such as poles or columns as ignored background, not as one of the 8 monitored object classes. The false positive object then cascades into incorrect zone state, spurious event feed entries, and operator confusion.

## Reproduction Steps

1. Open the area dashboard for camera `BAI-KIEM`.
2. Observe the tall vertical pole near the right side of the frame.
3. Wait for the detector to classify that structure.
4. Notice that it is labeled as `Xe cẩu` instead of being ignored as static background.

## Root Cause

`TASK-007` owns the logic that maps raw open-vocabulary detections into the canonical 8 classes, inside `AIVisionPipeline`. The current design combines three things that together leave a gap:

- permissive crane-oriented prompts for port equipment — `RICH_CLASS_PROMPTS` explicitly includes `"port crane"`, `"container crane"`, `"gantry crane"`, `"crane"` (`backend/app/services/vision_pipeline.py`)
- exact-match ignore rules for pole-like prompts — `POLE_LIKE_BACKGROUND_CLASSES` only suppresses a detection when the raw class matches those exact prompt labels
- a very narrow geometric suppression rule — `is_pole_like_crane_false_positive()` only drops crane boxes that are both narrow and tall

Any wider pole-like structure that the model names with a crane-related label survives filtering and passes through as a valid canonical `crane` detection.

## Scope of Impact

- **Affected Tasks**: `TASK-007`
- **Affected Requirements**: `REQ-002`, `REQ-004`
- **Affected Files**:
  - `backend/app/services/vision_pipeline.py`

## Proposed Fix

1. Tighten the raw-class mapping and suppression logic inside `AIVisionPipeline`.
2. Revisit the prompt strategy for crane-related vocabulary in the area scene.
3. Add a scene-specific or geometry-aware false-positive filter if prompt tuning alone is insufficient.

- Should there be a camera-specific deny region / background mask for fixed structures in `BAI-KIEM`, or should this remain a model/pipeline-only fix?
