# BUG-001 - SQLite database path is not deterministic across backend launch directories

- Severity: major
- Affected requirements: `REQ-006`, `REQ-008`, `REQ-009`
- Owning task: `TASK-006` - SQLite and data access layer
- Discovered by: `TASK-019` CR-003 verification
- Recorded at: `2026-08-23T15:26:13+07:00`

## Expected

The backend should use one canonical SQLite database path for local development and runtime queries, independent of the process current working directory.

Operators and developers should be able to inspect the documented database file and see the same event rows returned by `GET /api/v1/events` and consumed by the UI.

## Actual

The active backend database URL defaults to `sqlite:///./sentri_ai.db`, which resolves relative to the process current working directory.

The project `.env` defines `SENTRIAI_DB_PATH=backend/db/sentriai.db`, but `Settings` does not expose that variable and the database engine only uses `settings.DATABASE_URL`. As a result, the configured-looking `SENTRIAI_DB_PATH` is ignored.

When backend code is launched from `D:\Hilab\Project34\backend`, the relative SQLite file resolves to `D:\Hilab\Project34\backend\sentri_ai.db`. Inspecting `D:\Hilab\Project34\sentri_ai.db` or `.env`'s `backend/db/sentriai.db` cần therefore show no matching rows even while the UI is populated from the running backend.

Observed:

```text

DATABASE_URL=sqlite:///./sentri_ai.db
has_SENTRIAI_DB_PATH=False
resolved_relative_db=D:\Hilab\Project34\backend\sentri_ai.db
```

Supporting inspection:

- `.env` defines `SENTRIAI_DB_PATH=backend/db/sentriai.db`.
- `backend/app/core/config.py` defines `DATABASE_URL: str = "sqlite:///./sentri_ai.db"` and has no `SENTRIAI_DB_PATH` field.
- `backend/database/engine.py` calls `get_sqlite_engine()` and uses `settings.DATABASE_URL`.

## Minimal Failing Case

1. Configure or document one expected DB path through `.env` using `SENTRIAI_DB_PATH`.
2. Start backend from a different working directory while `DATABASE_URL` remains `sqlite:///./sentri_ai.db`.
3. Runtime writes events to a cwd-relative `sentri_ai.db`.
4. Developer inspects the expected configured path or project-root DB.
5. The inspected DB does not match UI/API-visible event rows.

## Root Cause

`TASK-006` database configuration uses a cwd-relative SQLite `DATABASE_URL` default and ignores the existing `SENTRIAI_DB_PATH` environment variable because the settings model has `extra="ignore"` and no translation from `SENTRIAI_DB_PATH` to `DATABASE_URL`.

This is a data-layer ownership issue rather than a frontend bug. `TASK-017` and `TASK-019` expose the symptom because area event persistence and verification rely on the same database engine.

## Risk

- Operators may inspect the wrong SQLite file and conclude event persistence is broken.
- Future chatbot/Text-to-SQL work cần target a stale or empty DB path.
- Historical event migration/backfill decisions become unreliable because there are multiple plausible local DB files.

## Regression Test

No regression test was added in this bug-recording step because the request scope is documentation/diagnosis only.

Recommended failing regression test for the fix owner:

1. Set a temp absolute SQLite `DATABASE_URL`.
2. Initialize the database through `backend.database.engine`.
3. Insert an event through the repository.
4. Assert the row appears in the exact configured path.
5. Assert `SENTRIAI_DB_PATH` is either removed from `.env.example` or deterministically translated into `DATABASE_URL`.

## Recommended Fix Phạm vi

1. Choose one canonical local DB location.
2. Replace the cwd-relative default with a project-root absolute SQLite URL, or require `DATABASE_URL` explicitly.
3. Remove `SENTRIAI_DB_PATH` from `.env`/`.env.example`, or support it intentionally in `Settings`.
4. Document the canonical DB path for local development and chatbot queries.
5. Decide whether existing rows in `backend/sentri_ai.db` should be migrated into the canonical DB.
