# BUG-001 — Area event feed loses zone name in integrated UI

- Severity: major
- Affected requirements: `REQ-002`, `REQ-009`
- Affected tasks: `TASK-017`, `TASK-018`

## Expected

`Area Security Dashboard` event feed should show the violated or allowed zone name for each area event so operators cần see where the event occurred.

## Actual

Frontend maps area events from `evt.zone_name`, but backend `GET /api/v1/events` response model does not expose `zone_name`. The UI therefore falls back to `'Ngoài zone'` instead of the actual zone name.

## Reproduction

1. Open [AreaSecurityDashboard.tsx](D:/Hilab/Project34/frontend/src/pages/AreaSecurityDashboard.tsx) and inspect the event mapping at line using `evt.zone_name || 'Ngoài zone'`.
2. Open [events.py](D:/Hilab/Project34/backend/app/api/v1/events.py) and inspect `EventResponse`.
3. Observe that `EventResponse` includes `zone_id` but no `zone_name`.
4. Any event returned from `GET /api/v1/events` therefore cannot satisfy the frontend's `zone_name` expectation.

## Evidence

- Frontend expectation: [AreaSecurityDashboard.tsx](D:/Hilab/Project34/frontend/src/pages/AreaSecurityDashboard.tsx)
- Backend response model: [events.py](D:/Hilab/Project34/backend/app/api/v1/events.py)
- Search evidence captured during verification:
  - `frontend/src/pages/AreaSecurityDashboard.tsx:111: zone: evt.zone_name || 'Ngoài zone',`
  - `backend/app/api/v1/events.py` contains helper-local `zone_name` fields for live detection formatting, but `EventResponse` omits `zone_name`

## Risk

Operators lose the location context of area events in the event lane, which weakens the acceptance goal that area events and alerts remain clearly usable after the metadata-lane split.
