# BUG-002 - Area event feed appears populated while inspected `sentriai.db` has no matching events

- Severity: major
- Affected requirements: `REQ-002`, `REQ-004`, `REQ-008`, `REQ-009`
- Affected tasks: `TASK-017`, `TASK-018`, `TASK-019`

## Expected

The database file inspected by operators/developers should match the event source used by `GET /api/v1/events` and the Area Dashboard event feed.

When the UI shows area violations, those rows should be visible in the expected SentriAI SQLite database, including event type, severity, zone/camera context, and clip handoff fields.

## Actual

The frontend Area Dashboard shows repeated `ZONE_VIOLATION` events such as `Xe nang` / `Xe con` at around `10:07` to `10:14`, but inspecting the expected `sentriai.db`/root DB cần show no matching rows.

The rows do exist in `D:\Hilab\Project34\backend\sentri_ai.db`, while `D:\Hilab\Project34\sentri_ai.db` is empty. The configured `.env` variable `SENTRIAI_DB_PATH=backend/db/sentriai.db` is not used by the backend database engine.

## Reproduction

1. Open Area Dashboard and observe the `Su kien khu vực / Realtime Feed` list.
2. Inspect `D:\Hilab\Project34\sentri_ai.db` or the configured `SENTRIAI_DB_PATH`.
3. Observe no matching rows.
4. Inspect `D:\Hilab\Project34\backend\sentri_ai.db`.
5. Observe the rows shown in the UI, including `evt-live-8caba202` at `2026-08-20 10:14:26.853018`.

## Evidence

- `D:\Hilab\Project34\sentri_ai.db`: `count=0`
- `D:\Hilab\Project34\backend\sentri_ai.db`: `count=75`
- Latest backend DB rows include:
  - `evt-live-8caba202`, `2026-08-20 10:14:26.853018`, `BAI-KIEM`, `zK3`, `ZONE_VIOLATION`, severity `3`, `Xe nang`
  - `evt-live-13d53204`, `2026-08-20 10:14:16.846268`, `BAI-KIEM`, `zK3`, `ZONE_VIOLATION`, severity `3`, `Xe nang`
  - `evt-live-7c3d5dc6`, `2026-08-20 10:08:45.844988`, `BAI-KIEM`, `zK2`, `ZONE_VIOLATION`, severity `3`, `Xe con`
- `.env` defines `SENTRIAI_DB_PATH=backend/db/sentriai.db`.
- `backend/app/core/config.py` defines `DATABASE_URL: str = "sqlite:///./sentri_ai.db"`.
- `backend/database/engine.py` uses `settings.DATABASE_URL`, not `SENTRIAI_DB_PATH`.
- When backend is started with current working directory `D:\Hilab\Project34\backend`, `sqlite:///./sentri_ai.db` resolves to `D:\Hilab\Project34\backend\sentri_ai.db`.
- Frontend maps event `zone` using `evt.zone_name || 'Ngoài zone'`, but `EventResponse` still omits `zone_name`, so existing rows with `zone_id=zK2/zK3` display as `Ngoài zone`.

## Risk

Operators and developers cần inspect the wrong database and conclude that event persistence is broken, while the UI is reading another SQLite file through the running backend. This also risks chatbot development targeting the wrong DB path and missing historical violation rows.

Existing event rows also still point to source video paths such as `/videos/KiemHoa-Hik (1).mp4` and have `bbox=null`, so they are not yet suitable evidence rows for the planned chatbot clip UX.

## Diagnosis

### Traceability

- Requirements: `REQ-002`, `REQ-004`, `REQ-005`, `REQ-008`, `REQ-009`
- Related prior defect: `.delivery/tasks/TASK-019/BUG-001.md`
- Affected runtime paths: `GET /api/v1/events`, Area Dashboard event feed, SQLite event storage, future chatbot event query path
- REQ-005 relevẫnce: zone configuration exists and event rows carry `zone_id`, but the event API/UI integration does not resolve that zone configuration back into `zone_name`.

### Minimal Failing Case

1. Use a relative SQLite URL: `sqlite:///./sentri_ai.db`.
2. Start or import backend code with current working directory `D:\Hilab\Project34\backend`.
3. Backend writes events to `D:\Hilab\Project34\backend\sentri_ai.db`.
4. Inspect `D:\Hilab\Project34\sentri_ai.db` or `.env` `SENTRIAI_DB_PATH=backend/db/sentriai.db`.
5. The inspected DB does not contain the UI-visible events.

The separate `Ngoài zone` symptom reduces to:

1. Event rows contain `zone_id` such as `zK2` or `zK3`.
2. `EventResponse` exposes `zone_id` but not `zone_name`.
3. Frontend reads `evt.zone_name || 'Ngoài zone'`.
4. UI displays `Ngoài zone` despite the row belonging to a zone.

### Root Cause

Primary root cause: database path ambiguity. The backend database engine uses `settings.DATABASE_URL`, whose default is the relative path `sqlite:///./sentri_ai.db`. Relative SQLite paths resolve against the process current working directory, so different launch directories produce different physical DB files.

The `.env` value `SENTRIAI_DB_PATH=backend/db/sentriai.db` does not affect the active SQLAlchemy engine because `Settings` does not define or translate `SENTRIAI_DB_PATH`; it only defines `DATABASE_URL`. As a result, the expected `sentriai.db` path and the actual event DB path diverge.

Secondary root cause: event zone display schema mismatch. The UI expects `zone_name`, but `GET /api/v1/events` returns `EventResponse` without `zone_name`. That causes rows with valid `zone_id` to render as `Ngoài zone`.

Downstream symptom: existing rows were created by older persistence logic, so they have `bbox=null` and `video_clip_url=/videos/KiemHoa-Hik (1).mp4` rather than the newer `/media/clips/...` handoff path.

### Ownership

- Primary owner: backend implementation / database configuration owner.
- Secondary owner: backend API contract owner for `/api/v1/events` response shape.
- Frontend owner is affected but not primary; frontend is consuming the documented-looking `zone_name` field expectation already recorded in `BUG-001`.

### Regression Test

No production regression test was added in this diagnosis step because the diagnosis scope is under `.delivery/tasks/TASK-019/`.

Recommended failing tests for the fix owner:

1. Đãtabase configuration test:
   - Set `DATABASE_URL` to a known temp absolute SQLite path.
   - Start repository/session through `backend.database.engine`.
   - Assert events are written to that exact path.
   - Assert unsupported `SENTRIAI_DB_PATH` is either removed from `.env` or translated deterministically to `DATABASE_URL`.

2. Event API contract test:
   - Seed camera, zone, and event with `zone_id`.
   - Call `GET /api/v1/events?camera_id=BAI-KIEM`.
   - Assert response includes `zone_name` or frontend no longer expects it.

3. Historical data visibility test:
   - Query the same DB path used by the running backend and compare latest event IDs against the API result.

### Recommended Fix Phạm vi

1. Replace relative SQLite default with a deterministic project-root absolute DB URL, or explicitly require `DATABASE_URL` in `.env`.
2. Remove or support `SENTRIAI_DB_PATH`; do not leave it as a dead config variable.
3. Document the canonical DB file path used by local development and chatbot queries.
4. Extend `/api/v1/events` to include `zone_name` by joining/serializing the related `Zone`, or update frontend to derive zone name from cached zones by `zone_id`.
5. Decide whether to migrate/copy existing rows from `backend/sentri_ai.db` to the canonical DB and whether to backfill `video_clip_url`/`bbox` for chatbot development.

- Should historical rows in `backend/sentri_ai.db` be migrated to the canonical DB?
